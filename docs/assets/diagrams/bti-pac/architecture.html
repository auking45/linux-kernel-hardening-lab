🛡️ 시나리오 1: ARM64 BTI (Branch Target Identification) 전방향 무결성
간접 분기(BLR x20) 발생 시 CPU는 PSTATE.BTYPE을 0b10으로 설정하고, 타깃 메모리가 Guarded Page(PTE_GP)인지 확인합니다.
타깃의 첫 명령어가 유효한 Landing Pad(bti c 또는 paciasp)이면 정상이지만, 가젯 중간이나 비인가 위치로 점프하면 즉각 Branch Target Exception (ESR_EL1.EC=0x0D / Oops - BTI)을 발생시킵니다.

🔐 시나리오 2: ARM64 PAC (Pointer Authentication Code) 후방향 반환 주소 보호
함수 진입 시 paciasp 명령어가 비밀 키(Key A)와 스택 포인터(SP)를 결합하여 반환 주소(LR / x30)의 상위 미사용 비트(54:48)에 암호화 서명(PAC)을 삽입합니다.
스택 버퍼 오버플로우로 LR이 1비트라도 변조되면, 에필로그의 autiasp 검증 시 FPAC 예외(ESR_EL1.EC=0x1C / Oops - FPAC) 또는 변조 주소 오류를 발생시켜 ROP 공격을 원천 차단합니다.

⚠️ 시나리오 3: 베이스라인 미적용 취약 환경 (BTI & PAC Disabled)
CONFIG_ARM64_BTI 및 CONFIG_ARM64_PTR_AUTH가 비활성화된 커널에서는 다음과 같은 보안 취약점이 그대로 노출됩니다:
1. 전방향 무방비: 랜딩 패드가 없는 bti_nobti_target으로 간접 분기해도 CPU가 예외를 발생시키지 않고 임의 코드를 실행(JOP 허용).
2. 후방향 무방비: LKDTM CFI_BACKWARD 트리거 시 스택 반환 주소가 변조되어도 하드웨어 서명 검증 없이 리디렉션 성공(FAIL: stack return address was redirected!).

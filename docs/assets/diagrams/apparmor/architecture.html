🔍 Path-Based Confinement Pipeline & DFA Evaluation

AppArmor는 프로세스가 파일에 접근할 때 dentry 계층을 순회하여 **정규화된 정규 경로(Canonical Path)**를 합성한 후, 커널에 사전 컴파일된 **결정적 유한 오토마톤(DFA)** 엔진을 통해 $O(1)$ 속도로 규칙을 대조합니다.

📜 커널 AppArmor 감사 로그 (auditd / dmesg)

[ 0.145000] AppArmor: AppArmor Filesystem Enabled
[ 0.145100] AppArmor: Loaded profile 'vuln_apparmor_service' (enforce)
[Ready] 상단 툴바에서 요청 작업과 모드를 선택한 후 [단계별 실행] 또는 [자동 실행]을 클릭하십시오.

📋 활성 프로필 선언 (`/etc/apparmor.d/vuln_service`)

profile vuln_apparmor_service /bin/exploit_apparmor {
    # 1. 파일시스템 규칙
    /home/lab/** r,             # 일반 홈 디렉터리 읽기 허용
    deny /tmp/secret_token rw,  # 비밀 토큰 접근 엄격 거부

    # 2. 네트워크 규칙
    deny network raw,           # Raw 패킷 스니핑/인젝션 차단
    
    # 3. 프로세스 추적 규칙
    deny ptrace,                # 타 프로세스 메모리 조작 차단
}

⚖️ Complain Mode (학습/감사) vs Enforce Mode (강제 차단)

1. Complain / Learning Mode (Baseline)

새로운 애플리케이션 도입 시 필요한 권한을 파악하기 위한 학습 모드입니다.

  • 접근 제어 판정: 위반이 발생해도 동작을 차단하지 않고 허용(ALLOWED)함.
  • 로그 형식: apparmor="AUDIT" ... (complain) 태그와 함께 dmesg에 상세 출력.
  • 보안 수준: 공격 차단 불가능 (Baseline 취약 상태).
  • 주 용도: aa-logprof 도구를 사용한 프로필 자동 프로파일링 및 튜닝.

2. Enforce Mode (Hardened)

프로덕션 배포 시 인가되지 않은 모든 자원 접근을 즉각 격리/차단하는 방어 모드입니다.

  • 접근 제어 판정: 프로필에 명시되지 않은 작업에 대해 즉시 -EACCES / -EPERM 거부(DENIED).
  • 로그 형식: apparmor="DENIED" ... (enforce) 태그와 함께 시스템 감사 이벤트 발생.
  • 보안 수준: 샌드박스 완벽 유지, 원격 RCE 페이로드의 호스트 장악 차단.
  • 주 용도: 컨테이너 런타임(Docker/K8s 기본 프로필) 및 엔터프라이즈 데몬 방어.

📊 Linux MAC 메커니즘 심층 비교: AppArmor vs SELinux

비교 항목 전통적 DAC AppArmor (경로 기반 MAC) SELinux (레이블 기반 MAC)
접근 통제 기준 소유자 UID/GID 및 파일 퍼미션 (rwxrwxrwx) 정규화된 경로명 (Canonical Path) 확장 속성(xattr) 보안 컨텍스트 레이블
관리 복잡도 매우 낮음 낮음 ~ 보통 (직관적 와일드카드) 매우 높음 (수만 개의 Type & Rule)
하드링크 / 파일 이동 영향 없음 경로가 변경되면 새로운 규칙이 적용됨 아이노드(xattr)에 레이블이 보존되어 안전
컨테이너 런타임 친화성 미흡 (루트 권한 공유 취약) 매우 우수 (Docker/K8s 기본 탑재) 보통 (복잡한 MCS/MLS 레이블링 필요)
커널 평가 엔진 인라인 비트마스크 검사 결정적 유한 오토마톤 (DFA) 액세스 벡터 캐시 (AVC)
주요 채택 배포판 모든 유닉스/리눅스 Ubuntu, Debian, openSUSE RHEL, Fedora, CentOS, Android

🧮 Forward-Edge kCFI vs Fine-Grained CFI
과거 Clang Forward-Edge CFI는 전체 커널 컴파일 시 거대한 점프 테이블(Jump Table)을 빌드하여 런타임 LTO 오버헤드와 모듈 로딩 문제를 유발함. kCFI(Kernel CFI)는 각 함수 시작 바로 앞(-4B)에 타입 해시를 독립 배치하여 커널 LTO 없이도 완벽한 모듈 호환성과 1% 미만의 극저부하를 달성함.
🧱 Hardware IBT (Intel CET) & ARM64 BTI
x86-64 IBT(Indirect Branch Tracking)는 간접 점프 직후 CPU가 WAIT_FOR_ENDBR 상태로 진입하여 첫 명령어가 ENDBR64가 아닐 경우 즉시 #CP 예외를 발생시킴. ARM64의 BTI(Branch Target Identification) 역시 BTI c 랜딩패드가 누락된 간접 점프를 하드웨어 수준에서 차단함.
🔙 Backward-Edge 보호: Shadow Call Stack & SHSTK
kCFI와 IBT가 함수 호출 지점(Forward-Edge: call *%rax)을 보호한다면, Shadow Call Stack (SCS) 및 Intel CET SHSTK는 함수 반환 주소(Backward-Edge: ret)를 격리된 전용 스택에 이중 보관하여 ROP(Return-Oriented Programming)를 100% 원천 봉쇄함.
🛡️ Defense-in-Depth 제어 흐름 방어 매트릭스
1단계 CONFIG_CFI_CLANG(타입 시그니처 검증) + 2단계 CONFIG_X86_KERNEL_IBT(하드웨어 랜딩패드 강제) + 3단계 CONFIG_SHADOW_CALL_STACK(리턴 주소 보호) + 4단계 CONFIG_ARM64_PTR_AUTH(포인터 암호화 서명 PAC)로 모든 제어 흐름 왜곡을 원천 봉쇄함.

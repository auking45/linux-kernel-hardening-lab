x86 Intel CET: Kernel IBT & User Shadow Stack Linux 6.12+

1. x86_64 Hardened: Intel CET (IBT 순방향 + Shadow Stack 역방향 보호)
Intel CET는 하드웨어 수준에서 순방향(Forward-edge)과 역방향(Backward-edge) 제어 흐름을 동시에 강제함.
1) Kernel IBT (Indirect Branch Tracking): 모든 유효한 간접 분기 타깃 함수의 첫 명령어는 반드시 endbr64 (0xf3 0f 1e fa)여야 함. 간접 분기(call *%rax) 즉시 CPU는 WAIT_FOR_ENDBRANCH 상태로 전이하며, 다음 인스트럭션이 endbr64가 아닐 경우 즉시 #CP (Control Protection Exception, vector 21) 트랩을 발생시킴.
2) User Shadow Stack: 유저 공간의 반환 주소를 격리된 전용 섀도 스택 포인터(SSP / MSR_IA32_PL3_SSP)에 동시 기록하여, ret 시 메인 스택과 섀도 스택의 주소를 상호 대조함.
[대기 중] 위 버튼을 클릭하여 하드닝 상태의 IBT 및 섀도 스택 방어 메커니즘을 테스트하십시오.
2. x86_64 Baseline: 제어 흐름 보호 미적용 (JOP 및 ROP 성공)
베이스라인 커널(CONFIG_X86_KERNEL_IBT=n 및 CONFIG_X86_USER_SHADOW_STACK=n)에서는 컴파일러 플래그 -fcf-protection=none으로 빌드되어 endbr64 인스트럭션이 생성되지 않으며, 하드웨어 CET MSR이 비활성화됨. 공격자가 함수 포인터나 스택 반환 주소를 변조하면 CPU는 아무런 제약 없이 임의 코드를 실행함.
[대기 중] 베이스라인 커널의 무제한 분기 및 가젯 실행 위험을 확인하십시오.
3. ARM64 아키텍처 대비: BTI & PAC (Hardware CFI 대조)
ARM64 아키텍처는 Intel CET와 유사한 보안 목적을 달성하기 위해 별도의 하드웨어 확장 기능을 제공함:
1) 순방향 간접 분기 보호: Intel IBT(endbr64) vs ARM64 BTI(bti c / bti j, Branch Target Identification).
2) 역방향 반환 주소 보호: Intel Shadow Stack(하드웨어 섀도 스택 SSP) vs ARM64 PAC(Pointer Authentication Code, pacia/autia) 및 소프트웨어 Clang Shadow Call Stack(x18 전용 레지스터).
4. 하드웨어 CFI 종합 비교 & IBT CPU 상태 머신
Intel CET IBT는 하드웨어 파이프라인에서 CPU 상태를 실시간 감시함. 아래 상태 머신 시뮬레이터를 통해 간접 분기 발생 시의 상태 전이 과정을 단계별로 확인할 수 있음.
